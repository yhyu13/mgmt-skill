## 一、蒸馏流程

### 步骤

```
1. 选人（从候选清单中选，按优先级）
     ↓
2. 确定方法论清单（2-5个，按学科标签）
     ↓
3. 搜集素材（见下方素材管理）
     ↓
4. AI蒸馏（按MGMT-SKILL模板格式写MGMT-SKILL.md）
     ↓
5. 交叉校验（和已有蒸馏的方法论对比，填关联表）
     ↓
6. 推送到GitHub
```

### 每个步骤的输出

| 步骤 | 输出 | 存放位置 |
|------|------|---------|
| 1 | 选人决定 | raw/对话记录 |
| 2 | 方法论清单 | raw/对话记录 |
| 3 | 素材索引 | `distill/sources/[person]-sources.md` |
| 4 | MGMT-SKILL.md | `mgmt-skills/individual/[person]/` |
| 5 | 交叉关联 | MGMT-SKILL.md内"与其他方法论的关系"章节 |
| 6 | git push | GitHub |

## 二、素材管理（原文留不留？）

### 原则：索引留，原文不留

| 素材类型 | 存什么 | 不存什么 | 理由 |
|---------|--------|---------|------|
| 书籍 | 书名+章节+核心摘录（每章≤500字要点） | 全书扫描/PDF | 版权+体积，摘录够蒸馏用 |
| 文章/博客 | URL+标题+核心观点摘要 | 全文复制 | 链接可追溯，摘要够用 |
| 演讲/访谈 | URL+时间戳+关键语录 | 完整视频/音频 | 体积太大，语录够用 |
| 案例数据 | 具体数字+来源 | 原始报告 | 数字可验证即可 |

### 素材索引文件格式

每个蒸馏对象一个索引文件：`distill/sources/[person]-sources.md`

```markdown
# [人名] 蒸馏素材索引

> 蒸馏日期：YYYY-MM-DD
> 蒸馏状态：✅已完成 / ⬜进行中

## 一、核心著作

| # | 书名 | 章节 | 核心摘录 | 蒸馏使用 |
|---|------|------|---------|---------|
| 1 | 《书名》 | 第X章 | 500字要点 | [methodology-name].md |

## 二、文章/博客

| # | 标题 | URL | 核心观点 | 蒸馏使用 |
|---|------|-----|---------|---------|
| 1 | 标题 | URL | 3-5句摘要 | [methodology-name].md |

## 三、演讲/访谈

| # | 标题 | URL | 关键语录 | 蒸馏使用 |
|---|------|-----|---------|---------|
| 1 | 标题 | URL | 时间戳+语录 | [methodology-name].md |

## 四、案例数据

| # | 数据点 | 来源 | 蒸馏使用 |
|---|--------|------|---------|
| 1 | 具体数字 | 来源 | [methodology-name].md |
```

### 为什么不存原文？

1. **版权**：书籍/文章全文存储有版权风险，开源项目尤其敏感
2. **体积**：100人×5本书×300页 = 15万页，不现实
3. **可追溯**：索引文件记了书名+章节+摘要，需要时随时可以找到原文
4. **蒸馏的本质**：MGMT-SKILL.md本身就是原文的结构化提炼，不是原文的替代

### 什么情况下需要回看原文？

- 蒸馏时发现摘要不够详细 → 按索引找到原书对应章节
- 后续补充新方法论 → 按索引找到原书新章节
- 交叉校验时发现矛盾 → 回到原文确认

## 三、版本迭代（后续怎么补充？）

### 迭代场景

| 场景 | 触发条件 | 怎么做 |
|------|---------|--------|
| 补充新方法论 | 发现遗漏的重要方法论 | 新建MGMT-SKILL.md，更新素材索引 |
| 补充新素材 | 读了新书/看了新演讲 | 更新素材索引，在MGMT-SKILL.md的更新日志追加 |
| 修正错误 | 发现事实性错误 | 直接修改MGMT-SKILL.md，更新日志记录 |
| 增加交叉关联 | 蒸馏了新人物/新组织 | 在"与其他方法论的关系"章节追加 |
| 学科横切 | 个人蒸馏积累5+人 | 新建discipline/目录下的横切文件 |

### 迭代操作检查清单

#### 场景1：补充新方法论

- [ ] 确认遗漏的方法论名称+学科标签
- [ ] 在 `mgmt-skills/individual/[person]/` 下新建 `[person]-[methodology].md`
- [ ] 按MGMT-SKILL模板填写完整内容
- [ ] 在 `distill/sources/[person]-sources.md` 追加新素材条目
- [ ] 在README的方法论全景表追加一行
- [ ] git add + commit + push

#### 场景2：补充新素材（读了新书/看了新演讲）

- [ ] 在 `distill/sources/[person]-sources.md` 对应章节追加条目
- [ ] 判断新素材是否改变已有MGMT-SKILL.md内容
  - 是 → 修改对应MGMT-SKILL.md，在更新日志追加一行
  - 否 → 仅更新素材索引
- [ ] git add + commit + push

#### 场景3：修正错误

- [ ] 定位错误所在MGMT-SKILL.md
- [ ] 直接修改错误内容
- [ ] 在更新日志追加：`| YYYY-MM-DD | 修正[错误描述] |`
- [ ] git add + commit + push

#### 场景4：增加交叉关联（蒸馏了新人物/新组织）

- [ ] 找到受影响的已有MGMT-SKILL.md
- [ ] 在"与其他方法论的关系"表格追加一行
- [ ] 在更新日志追加：`| YYYY-MM-DD | 新增与[新方法论]的交叉关联 |`
- [ ] 如果关联涉及前提条件/冲突点 → 同步更新"适用场景"或"诚实边界"
- [ ] git add + commit + push

#### 场景5：学科横切（个人蒸馏积累5+人）

- [ ] 确认横切学科（如 hr / marketing / leadership）
- [ ] 在 `mgmt-skills/discipline/` 下新建 `[discipline]-[topic].md`
- [ ] 按学科横切模板填写（前提条件矩阵 + 方法论对比）
- [ ] 在README的学科横切表追加一行
- [ ] git add + commit + push

### MGMT-SKILL.md的版本管理

每个MGMT-SKILL.md底部有更新日志：

```markdown
## 更新日志

| 日期 | 更新内容 |
|------|---------|
| 2026-06-30 | 初始版本 |
| 2026-07-15 | 补充第X章新素材，修正Y模块描述 |
| 2026-08-01 | 新增与[新蒸馏人物]的交叉关联 |
```

### 素材索引的版本管理

素材索引文件顶部记录蒸馏状态和最后更新日期：

```markdown
> 蒸馏日期：2026-06-30
> 最后更新：2026-07-15
> 蒸馏状态：✅已完成
> 方法论数：5
> 待补充：[如果有新素材待处理]
```

## 四、蒸馏质量标准

### 必须满足

- [ ] 每个模块有定义/输入/输出/关键动作/常见误区
- [ ] 决策启发式≥7条
- [ ] 与其他方法论的关系≥5个
- [ ] 实施检查清单≥10项
- [ ] 诚实边界≥6条
- [ ] frontmatter字段完整（name/source_type/person/role/category/discipline/nuwa_skill/tags/license）
- [ ] 版权声明+参考来源列表

### 加分项

- [ ] 有对比表（和已有蒸馏的方法论对比）
- [ ] 有核心公式/核心洞察
- [ ] 和nuwa-skill重叠人物有互引
